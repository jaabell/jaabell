# Working in this repository

- This is a Pelican site: articles live in `content/posts/`, pages in `content/pages/`. `pelicanconf.py` controls URLs, plugins, and copied assets (`content/images/`, `content/pdfs/`, `content/extra/CNAME`, `content/favicon.ico`); other files under `content/extra/` are not copied by default.
- Run commands from the repo root: `make devserver PORT=8000` for local preview, `make html` for a development build. `make publish` uses `publishconf.py` (production URL, feeds, and `DELETE_OUTPUT_DIRECTORY=True`).
- The active theme is **`../blog2theme`**, not this repo's `theme/`; repo-local `templates/base.html`, `templates/index.html`, and `templates/partial/latest.html` override its visitor map and homepage. `content/pages/04publications.md` opts into `templates/publications.html` via its `Template` metadata. Plugins are loaded from `../pelican-plugins/`. These sibling directories must be available. The config also names `pelican_fontawesome` and Markdown `mdx_include`; check those dependencies if a build fails. There is no repo-local dependency manifest.
- `output/` is a Git submodule for `jaabell.github.io`, not disposable local output. For isolated build checks, use `pelican content -o /tmp/opencode/blog-preview -s pelicanconf.py` instead of writing to `output/`. In particular, production builds delete output contents.
- `Makefile`'s `github` target publishes via `ghp-import` to `master`; `deploy.sh` instead copies the production build into sibling `../jaabell.github.io` and commits/pushes there. Treat both as deployment actions, not verification commands.
